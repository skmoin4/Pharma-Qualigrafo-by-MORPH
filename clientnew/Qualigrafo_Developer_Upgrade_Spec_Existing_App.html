Qualigrafo – Developer Upgrade Specification

Upgrade the existing Pharma application. Do not rebuild the product from scratch.

OLD UI + NEW MULTI-INDUSTRY CAPABILITIES

Developer Rule #1

Keep the existing Qualigrafo architecture, login, sidebar, Portfolio, My Work, Regulatory Watch, Requirement Library, Users & Access, current project wizard and existing Pharma data model.

The new requirement is an extension of the existing product, not a replacement UI.

1. Existing Project Creation Wizard – Upgrade Mapping

Current wizard observed: Basics → Scope & Markets → Registers → Team → Review.

Current ScreenActionDeveloper Update
Step 1 – Basics MODIFY Keep Project Name, Project Code, Client, Site/Location, Plant Country.
Rename Plant Country to Project Country so it works for every industry.
Keep country-linked authority logic, but make it industry-aware.

Step 4 – Team EXPAND Keep current team assignment. Add Project Manager, Discipline Lead, Author, Checker, Reviewer, Approver, QA/QC, Client, Contractor and Auditor roles. Add RACI / approval responsibility.
Step 5 – Review EXPAND Keep the review page. Show complete project classification before creation:
Industry → Facility → Service → Scope → Stage → Disciplines → BIM Level → Markets/Authorities → Registers → Team.

16. Final Developer Summary

Do not delete the old Pharma system.

1. Keep its authentication, existing modules, Pharma registers, market logic, audit/signature concepts.
2. Convert Pharma-specific project setup fields into reusable multi-industry fields.
3. Add Hospital, Energy/High-Tech and Common templates beside Pharma.
4. Use the same task, document, revision, approval, RFI and handover engine for every industry.
5. Keep industry-specific logic as configurable templates, not separate applications.
